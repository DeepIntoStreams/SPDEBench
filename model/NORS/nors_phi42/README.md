# NORS for renormalized Phi42

This directory is a self-contained NORS baseline for the full renormalized
two-dimensional Phi42 trajectory. It does not import the implementation in the
parent `model/NORS` directory.

## Features

`Phi42FeatureBuilder` maps cumulative Brownian fields and initial conditions to
seven full-time model features:

1. `I[xi]`
2. `I_c[u_0]`
3. `I[I[xi]]`
4. `I[I_c[u_0]]`
5. `I[(I[xi])^2]`
6. `I[(I[xi])(I_c[u_0])]`
7. `I[(I_c[u_0])^2]`

The default convention matches SPDEBench Phi42 generation:

- `W` is a cumulative Brownian field;
- `xi = 0.1 * diff(W) / dt`;
- the heat operator has diffusion coefficient one and periodic boundary
  conditions;
- output ordering is `[sample, time, x, y, feature]`.

Training defaults reproduce the established Phi42 FNO/NSPDE protocol:

- `max_time=250` and `sub_t=5`, giving indices `0,5,...,245`;
- the legacy NumPy permutation for identical seed-dependent data splits;
- 840/180/180 train/validation/test samples;
- modes 16/16/16, width 32, four Fourier layers, and batch size 10;
- scheduler patience 50, factor 0.1, threshold 1e-6;
- early-stopping patience 80 and minimum improvement `delta=0.0002`.

These are standard width-two NORS features evaluated against a renormalized
target dataset. They do not add new Wick/counterterm feature channels.

## Training

From the repository root:

```bash
python -m model.NORS.nors_phi42.train \
  --data-path "data_gen/results/Phi42+/Phi42+_reno_xi_u0_eps_128_1200.mat"
```

The first run builds a memory-mapped feature cache because the full
`[1200,T,X,Y,7]` tensor is large. Later runs reuse it. To force regeneration:

```bash
python -m model.NORS.nors_phi42.train \
  --data-path "/path/to/Phi42+_reno_xi_u0_eps_128_1200.mat" \
  --rebuild-features
```

Useful memory controls:

```bash
python -m model.NORS.nors_phi42.train \
  --data-path "/path/to/renormalized.mat" \
  --feature-batch-size 4 \
  --batch-size 2
```

### Streaming HDF5 training at 128 x 128

HDF5 files generated by `data_gen/examples/gen_phi42_h5.py` are read lazily.
The first run creates a temporally subsampled target cache and the seven-channel
feature cache without loading the full HDF5 file into RAM. Both caches record
completed sample counts and resume after an interrupted cache build.

For the fixed-initial-condition, `eps=128` dataset:

```bash
python -m model.NORS.nors_phi42.train \
  --data-path "/workspace/results/Phi42+/Phi42+_xi_eps128_sigma0.1_seed42_1200.h5" \
  --output-dir "/workspace/result/NORS_new_Phi42/seed_3407" \
  --checkpoint-name "NORS_new_Phi42_eps128_best_val.pt" \
  --max-time 250 \
  --sub-t 5 \
  --sub-x 1 \
  --diffusion 1.0 \
  --noise-scale 0.1 \
  --feature-batch-size 1 \
  --ntrain 840 \
  --nval 180 \
  --ntest 180 \
  --batch-size 1 \
  --gradient-accumulation-steps 10 \
  --num-workers 0 \
  --epochs 1000 \
  --learning-rate 0.001 \
  --weight-decay 0.0001 \
  --modes-x 16 \
  --modes-y 16 \
  --modes-t 16 \
  --width 32 \
  --depth 4 \
  --time-padding 6 \
  --scheduler-patience 50 \
  --scheduler-factor 0.1 \
  --scheduler-threshold 0.000001 \
  --early-stopping 80 \
  --delta 0.0002 \
  --print-every 20 \
  --seed 3407 \
  --device cuda
```

At `1200 x 50 x 128 x 128`, the target cache is about 3.9 GB and the
seven-channel feature cache is about 27.5 GB. Do not pass
`--rebuild-features` when resuming an interrupted cache build. Batch size one
with ten accumulation steps preserves the original effective training batch
size of ten while reducing peak GPU memory.

Outputs are written to `model/result/NORS_Phi42` by default:

- cached `.npy` features and JSON metadata;
- `best_model.pth` (or the value passed to `--checkpoint-name`);
- `metrics.json` containing train/validation/test relative L2 errors.

The log reports `early_stop=current/80`. The counter resets only when validation
loss improves by at least `delta=0.0002`. If training is stopped with Ctrl+C
after at least one checkpoint has been saved, the script loads that best
checkpoint and still writes the final metrics.

### Five training seeds

The multi-seed driver runs sequentially to avoid placing five 67M-parameter
models on the GPU at once. All seeds reuse one feature cache.

```bash
python -m model.NORS.nors_phi42.train_seeds \
  --data-path "/workspace/results/Phi42+/datasetPhi42+_reno_xi_eps128_1200.mat" \
  --output-dir "/workspace/result/NORS_Phi42" \
  --seeds 3407 3408 3409 3410 3411
```

Completed seed directories are reused when the command is restarted. Pass
`--rerun` only to retrain all seeds. Training metrics are aggregated in
`training_seed_summary.json`.

## Independent evaluation

The evaluator mirrors `model/FNO/eval2d.py`: it evaluates one checkpoint on
independently generated MAT datasets, reports each dataset separately, and
prints mean ± standard deviation. It additionally caches each dataset's seven
NORS features and reports feature preparation separately from model inference.

```bash
python -m model.NORS.nors_phi42.eval \
  --checkpoint "/workspace/result/NORS_Phi42/seed_3407/best_model.pth" \
  --output-dir "/workspace/result/NORS_Phi42/seed_3407/evaluation" \
  --eval-data-paths \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10001_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10002_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10003_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10004_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10005_reno_xi_eps128_180.mat"
```

The evaluator saves:

- `predictions_dataset_1.pt` through `predictions_dataset_5.pt`, each containing
  `u_real` and `u_pred` in `[sample,x,y,time]` order;
- `evaluation_summary.json` with per-dataset results and mean ± std;
- memory-mapped feature caches under the evaluation output directory.

### Fill the five-seed table row

After all checkpoints exist, evaluate them and produce the NORS row for Table
18:

```bash
python -m model.NORS.nors_phi42.eval_seeds \
  --training-dir "/workspace/result/NORS_Phi42" \
  --seeds 3407 3408 3409 3410 3411 \
  --eval-data-paths \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10001_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10002_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10003_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10004_reno_xi_eps128_180.mat" \
    "/workspace/results/Phi42_evaluation_data/Phi42_test_seed10005_reno_xi_eps128_180.mat"
```

The driver reuses evaluation feature caches across model seeds and does not
save the roughly 30 GB of repeated prediction tensors unless
`--save-predictions` is supplied. For each training seed it first averages over
the independent test datasets, then reports mean ± sample standard deviation
across the five trained seeds. `table18_nors_summary.json` contains Rel. L2,
W1,2, Corr., AutoCorr., Sig-W1, and model inference time in milliseconds per
sample.
